# 分层关系、版本与冲突处理

## 分层模型

特征类型归一为 `gene / transcript / exon / CDS / other`。关系来源：

- GFF3：`Parent` 属性（可多父级，内部去重排序）；
- GTF：`gene_id` / `transcript_id` 推导出的两级关系；
- BED12：block 外显子的父级是行特征。

合法父子类型：

| 子 | 允许的父 |
| --- | --- |
| gene | 无，或 `other` |
| transcript | `gene`、`other` |
| exon / CDS | `transcript`、`gene`、`other` |

非法组合返回 `bad_parent_type`。

## 批次原子性

一次 `Commit`（或一次 `importer.Import`）是一个原子批次：

- 批次按 `(seqID,start,end,id)` 排序后处理，保证报错顺序确定；
- 任何一条记录失败（解析拒绝、关系/版本问题），整批不可见，
  修订号不前进，旧视图继续服务查询；
- 解析层存在拒绝记录时，`importer.Import` 默认**不提交**任何特征，
  并把逐行拒绝原因返回给调用方。

## 标识冲突

问题码（`graph.Problem.Code`）：

| code | 触发条件 |
| --- | --- |
| `duplicate_id` | 同一无版本 id 出现多次 |
| `duplicate_version` | 同一 id 的同一版本号再次提交 |
| `version_regression` | 新版本号不高于已保留版本 |
| `dangling_parent` | 父 id 在目录中不存在 |
| `self_reference` | 特征把自己列为父 |
| `cycle` | 父边形成环 |
| `bad_parent_type` | 父子类型组合非法 |

默认策略是 **ConflictReject**：绝不静默取其一。显式选择
**ConflictOverwrite** 时，允许用一个新的**无版本**特征替换旧的无版本
特征（版本化特征仍遵守下面的版本规则）。两种策略都会在提交结果中保留
来源信息，查询结果可解释。

## 版本规则

同一 id 可以保留多个版本，`Current` 指向最高版本：

- 空版本视为彼此相等且低于任何非空版本；
- 点分版本逐段比较：两段都是整数时按数值比较，`1.10 > 1.9`；
- 否则按字符串比较；前缀全部相等时段数多者更高，`1.2.1 > 1.2`；
- 提交更高版本 → 历史保留、当前指针前移；
- 提交相等版本 → `duplicate_version`；
- 提交更低版本 → `version_regression`。

旧版本仍可在快照中查看（`Snapshot.Features[id]` 为升序版本链），
查询默认只面向当前版本。

## 回滚与再导入

- `Rollback(to)` 把活动视图移动到较早修订号，并把回滚动作本身写入事件
  日志；重启重放后得到相同视图（可复现）。
- 回滚后再次提交是在被回滚到的基线上进行，历史日志中的旧事件不删除，
  只是不再属于活动谱系；活动视图由“回滚点之前、修订号 ≤ 目标”的提交
  重放得出。
- 因此“相同输入 + 相同事件历史 → 相同修订内容 → 相同查询结论”。

## 环形与悬空引用

关系校验在当前版本集合上进行：先收集父边，再用确定性顺序的 DFS 检测
自环与多节点环；悬空父级在环检测之前单独报告。任何问题都使整个批次
失败，因此不会产生“半连接”的目录。
