# 持久化、重建与恢复语义

## 磁盘布局

索引目录（默认 `.gaidx/`）：

| 文件 | 作用 |
| --- | --- |
| `events.jsonl` | 只追加的事件日志，每行一个带校验的 envelope |
| `snapshot.json` | 物化快照（加速打开；始终可由事件日志重建） |
| `manifest.json` | 指向快照的清单，含修订号、事件数、SHA-256 |
| `sources/*.src` | 可选：导入源文件副本（`CopySources`），便于重建 |
| `lock` | 进程级 `flock` 排他锁，防止双写 |

事件 envelope：

```json
{"payload": { ...事件本体... }, "checksum": "<sha256(原始payload字节)>"}
```

校验和覆盖 payload 的**原始字节**，因此任何位置的翻转（包括落在 JSON
结构性可忽略位置的破坏）都会被发现。

提交顺序（`Commit`）：

1. 在内存副本上完成整批校验与关系验证（失败则到此为止）；
2. 可选复制源文件；
3. 追加事件并 `fsync`；
4. 重写 `snapshot.json`、`manifest.json`（写临时文件 + `rename` 原子替换）；
5. 通过原子指针发布新快照。

## 并发可见性

- 查询路径**不加锁**：不可变 `graph.Snapshot` 存放在 `atomic.Pointer`
  中。重建/导入在完整构造并校验新快照后**一次性换指针**。
- 因此并发查询要么读到重建前的完整旧视图，要么读到重建后的完整新视图，
  不可能出现新旧特征混合、重复或遗漏。
- 写操作之间由互斥锁串行化；测试用 8 个读者 × 提交/回滚交替验证，
  数万个查询样本只可能等于两个已知的完整视图计数。

## 启动恢复决策表

| 现象 | 行为 |
| --- | --- |
| 空目录 | 创建空索引（修订号 0） |
| 最后一行不完整（崩溃发生在追加中途） | 安全丢弃该截断尾，从完整前缀恢复 |
| 完整事件行解析/校验失败 | 返回 `CorruptError`，**明确失败**，绝不返回可能错误的数据 |
| `snapshot.json`/`manifest.json` 缺失、哈希不符、修订/事件数不符 | 忽略快照，从事件日志重放并安全重建 |
| 事件日志与快照都损坏 | `CorruptError`；运维确认后可 `Purge()` 清空并重新导入 |
| 另一个进程已打开同一目录 | 因 `flock` 直接失败 |

设计原则是「要么明确失败，要么安全重建」：日志是唯一事实来源
（source of truth），快照只是可随时再生的加速器。

## 重建

- `Rebuild()` 重新读取事件日志、重放（含回滚语义）、校验关系后原子
  换入，并重写快照/清单；重建期间查询不中断。
- 修订号与事件数与重放结果一致时重建是幂等的。

## 查询语义

- 区间：半开重叠，端点相接不命中；
- 链：`StrandAny` / `StrandForward`（含无链）/ `StrandReverse`（含无链）
  / `StrandForwardOnly` / `StrandReverseOnly`；
- 类型：白名单（空表示全部）；
- `IncludeLineage`：把命中外显子/转录本的、与区间重叠的祖先补入结果；
- 输出按 `(start,end,id)` 排序，去重确定，多次调用结果逐字节一致。
